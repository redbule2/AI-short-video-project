# P1：人物载体：simple-human 图元

## 唯一推荐：内置图元 simple-human

导演台 13 个内置图元里有一个 `simple-human`，渲出来就是「方块身体 + 球头 + 蓝色眼条 + 蓝色胸条」——和参考图一致，无四肢、无骨骼、无 T-pose。

```json
{
  "id": "hero",
  "name": "男主",
  "semanticKind": "character",
  "kind": "model",
  "source": "primitive",
  "rigged": false,
  "visible": true,
  "opacity": 1,
  "color": "#d94b4b",
  "placementAnchor": "legacy-bottom-y-v1",
  "transform": {
    "position": {"x": 0, "y": 0, "z": 0},
    "rotation": {"x": 0, "y": 0, "z": 0},
    "scale": {"x": 1, "y": 1, "z": 1}
  },
  "primitive": "simple-human",
  "intrinsicGeometry": {"kind": "simple-human", "height": 1.75}
}
```

**一个 `simple-human` 就是一个人**，不用拼方块+球，也不用挂任何资源。

### 为什么不默认用库内人偶

| 问题 | 后果 |
| --- | --- |
| 不挂动作时是 T-pose | 画面难看，还得额外解释 |
| 挂动作要看 K 帧 | 每镜多几十分钟，白膜还看不出表演 |
| 动作 JSON 导入后不可预览 | 花了时间，验收不了 |
| 体型不统一 | 每个角色外形不一样，参考片不一致 |

**结论：默认不用。** 但用户明确要求人偶时不适用这一条——用户要求优先，按下一节的字段和动作规则执行。

### 人物本体必须标 character

**本体必须是 `semanticKind: "character"`。** 它是“这是人”的唯一凭据：占画面、切边、净空、越轴的核对都靠它找主体。

只有两种载体，同一片内统一：

| 载体 | 什么时候用 |
| --- | --- |
| `primitive: "simple-human"` 单对象 | **默认**。走位、构图、剪影 |
| 库内人偶 | **用户指定时**（用户优先），字段见下一节 |

**需要手部接触时，从 `simple-human` 体块内伸出长方体**：方块贴住躯干侧缘、伸到身体前方 0.3–0.4 m，标 `prop`、名字带角色 id。不拆成躯干、球头、四肢多个对象——对象多、比例要自己统一，且这套做法从未在端上验证过。

**关键只有一条：本体标 `character`，不要为了省事标成 `prop`。** 标成 `prop` 后，核对时找不到“人”，相机贴脸、主体占画面、切边全部不会去看。

实测：一次追逐把角色拆成「躯干+球头（composite）+ 双臂双腿（cube）」并全部标 `prop`，核对直接报“没有人物”，等于没查。

## 库内人偶（用户指定时）

**这是旁路，不是默认。** 用户明确要"库内人偶 / 骨骼人偶 / 有四肢的人"时，按用户要求做，不要用图元替代；**镜头、分镜、景别、运镜完全按 skill 的常规规则，不因为换成人偶而改变。**

本体字段（缺 resource 会 `invalid_document`）：

```json
{"id":"hero","name":"主角","semanticKind":"character","kind":"model",
 "source":"imported","rigged":true,
 "placementAnchor":"legacy-bottom-y-v1",
 "resource":{"provider":"catalog","kind":"model",
             "resourceId":"canonical:dpa_…","format":".fbx"}}
```

`director catalog --kind character` 有 12 个：男/女/少年/儿童/纤瘦/健壮/丰腴。

### 动作：可挂可不挂

| 需要什么 | 做法 |
| --- | --- |
| 表演（走、坐、打、喊） | `motion.add` 挂库内动作片段 |
| 写实定格、雕塑、超现实造型 | **不挂**，用整体 transform 摆位 |
| 走 / 跑 | path-traversal 片段（沿路径行走 1.75 m/周期、沿路径跑步 2.53 m/周期），位置关键帧负责路线 |

不挂动作时人偶就是 T-pose。**这可以是刻意的**，但要写进记录："刻意保持 T-pose，因为 ___"。既没挂动作、也没说明，才算出错。

### 挂动作的写法

为每个片段指定唯一的 `id`，`createdAt` 填写 ISO 8601 格式的创建时间，`resourceId` 使用动作目录返回的值。

```json
{"type":"motion.add","clip":{
  "id":"hero-walk","createdAt":"2026-01-01T00:00:00Z",
  "objectId":"hero",
  "motion":{"provider":"catalog","kind":"motion","resourceId":"canonical:dpa_…"},
  "startFrame":0,"sourceInFrame":0,"durationFrames":72,
  "speed":1,"loop":true,"transitionInFrames":0,"locomotionMode":"in-place"}}
```

要点：

- 片段默认是**原地**动作（`in-place`），位移靠位置关键帧，两者分工；
- 两段动作之间给 `transitionInFrames`（常用 6–12 帧），否则姿态跳变；
- 片段不够长时选 `loop:true` 或挑更长片段，不要硬拉 `speed`；
- 动作结束要停住，就缩 `durationFrames` 再补一个站定片段。

### 判断

- 人偶**整体平移/旋转、没有任何姿态变化**，且记录里没写"刻意 T-pose" → 视为漏挂动作；
- 人偶在动但姿态僵硬、贴地或悬空 → 检查片段长度与 `locomotionMode`；
- 用户要的就是 T-pose → 记录里写一句，正常交付。

## 尺寸与颜色

- `height` 必填（只写 `kind` 会 `invalid_document`）；成人 1.75、女性 1.65、儿童 1.20。
- `placementAnchor` 只接受 `legacy-bottom-y-v1`（脚底）；写 `center` 会 `invalid_document`。
- `position.y` = 地面高度；`color` 用来区分角色（红/蓝），不靠外形。

## 动作：整体 transform，不挂片段

| 动作 | 通道 | 要点 |
| --- | --- | --- |
| 走 / 跑 | `position.x/z` | 直线即可，速度按帧算 |
| 跳 | `position.y` | 0 → 1.2 → 0，前后各留 2 帧 |
| 转身 | `rotation.y` | 0 → 90 / 180 |
| 空翻 | `rotation.x` | **每段 ≤180°** |

**翻转的两个坑（实测）：**

1. `0 → 360` 会被归一化成 `0 → 0`，画面完全不动。必须拆三段 `0 → 120 → 240 → 360`。
2. 锚点在脚底，绕 X 转是**以脚为轴甩**。要绕身体中心翻，必须给位置打补偿：

```text
θ = 当前角度（弧度），H = 身高，C = 身体中心的空中位置
position.y = Cy - (H/2)·cosθ
position.z = Cz + (H/2)·sinθ
```

实测这个补偿在 90°–120° 附近会向镜头方向偏，**必须抽帧核对**；接受不了就改用圆柱（中心轴），或让空翻只做半程。

## 手部与道具：方块放身体前方

`simple-human` 没有手，所以握持靠**物体相对身体的位置**表达：

| 握持方式 | 方块/道具位置（相对身体） |
| --- | --- |
| 双手持物（箱、桶） | 正前 0.30–0.40 m，高 1.05–1.25 m |
| 单手持物（刀、杯） | 右侧前方 0.25 m，高 1.15 m |
| 高举 | 正前 0.15 m，高 1.60 m |

方块用 `cuboid` 0.12×0.12×0.30 或 `cube` `sideLength` 0.15；道具与方块同位置关键帧。不要试图在白膜里表达手指，握持方式写进给视频模型的说明。

## 一片只用一种载体

**同一部片里只用一种人物载体**：全 `simple-human`，或全库内人偶。不混用，也不混用圆柱。

| 情况 | 做法 |
| --- | --- |
| 需要人形轮廓 | 调 `height` 和 `color`，不换载体 |
| 需要中心轴翻转 | 用位置补偿，不换圆柱 |
| 需要手部接触 | 从人的体块内伸出长方体，仍用 `simple-human` |
| 用户指定库内人偶 | 该片统一改用库内人偶 + 库内动作片段 |
| 多人 | 同一做法、不同颜色 |

中途换载体，观众会以为换了人。

## 图元字段的坑

| 图元 | 必填 | 写错会 |
| --- | --- | --- |
| `cube` | `sideLength` | 写 width/height/depth 直接 `invalid_document` |
| `cuboid` | `width` / `height` / `depth` | — |
| `cylinder` | `radius` / `height` | — |

基础几何体的内禀尺寸不是 1×1×1：立方 **1.6×1×0.8**，圆柱直径 1、高 1。缩放按内禀尺寸换算。

## 预览参数

`director preview --long-edge` **只接受 1280 或 1920**，其他值直接报参数错误（`--long-edge must be 1280 or 1920`）。

## 调度与表演节拍

主次行动通过目标、进出画、近远变化、视线方向、发起/响应与停顿安排。库内可表演部分实际编排，细腻表情/口型/精确招式未实现不得写完成；视频生成不是3D预演自动附带步骤，按实际授权与能力处理。

记录每人站位/整体朝向、路线、预设与入点；倾听者不机械抢戏，主次节拍可错开，不用随机错开代替真实差异。用户指定整齐同步/夸张风格按原文保留。没有面部能力的简化人体不称已实现表情/台词。

### 关键反应的选材与预演

仅在反应或接力承担故事信息时，用选定角色、预设与计划景别预演最短关键段。设计顺序沿用[信息揭示顺序](story-and-camera.md#信息揭示顺序)。

1. **按镜头所需证据选角色。** 如果眼神、嘴部或微表情决定观众是否读懂，先看候选角色在该景别的实际能力。面部信息弱时，在自由项内选轮廓明显的姿态变化、停步、上身转向、可用手势或画内物件变化。原文锁定的表情、手势和行为按其精度核对，缺口单列。
2. **按实际动作选预设相位。** 看变化开始、幅度最大和落定的可见姿态。多人接力用不同的原状态、动作目的或清楚的画内提示区分发起与响应。同一预设可错时复用，按画面核对两人的角色差异和响应依据。只有反应先后可读时，记录到这一层。
3. **把短段放进实际构图。** 从触发前看到接收者改变状态，并核对观众能否认出最终对象。证据太小或被挡时先调遮挡、取景与停留。角色动作本身不清楚时先换已支持的片段或相位，再调整允许改变的站位、方向和物件关系。复用这个预演检查结果继续制作。

## 多主体交互

接触/共持/交接才列必要事件：全局时刻、双方目标、相对距离/朝向、动作起止、物件归属与结果；纯并行走路/独立群众不强加接触表。双方共享同一时间。用兼容预设与整体调度配合：能表达则验证；只能部分则标预演/缺口；缺关键行为停止该动作实现分支，联合调整受影响的自由动作、物件/遮挡与相机，或保留未完成。锁定行为不能暗改，不用无关动作或全身观察冒充原方案；用户明确批准代理时可交代理预演，但说明无真实行为，不计为原动作完成。

掌指只做可见性核对，不做数值判定。现有附件/持物预设核对明显脱手、穿入与归属，先换预设、相位或允许改变的整体位置；不扭腕/IK补救，不靠切镜遮挡掩盖失败。整体人物盒通过不证明精确接触。

## 走跑、群众与接地

走跑查真正path-traversal素材，核对步幅/距离驱动、源位移、循环、pathFacingEnabled与启停，见[timing-and-diagnostics](timing-and-diagnostics.md#持续动作循环)。先真实短片段验证再扩展，连续看滑步、复位与转弯；倒退/侧移的身体朝向不能被路径自动朝向覆盖。

群众各自保留路线、入出时刻与整体朝向，先主角/相机通道再外围；不默认全部灰色。支撑优先当前原生落地/路径和匹配预设，台阶不适配说明缺口，不逐关节锁脚。未变承载结果复用，最终基础目视。

整体可信包络参与场景/相机配对；真实蒙皮、内部肢体、掌指/布料未覆盖，不为此另造检测工具、不整对豁免人物与道具。保留实际角色/预设ID与片段参数，用起/事件/末、循环/切点和连续播放验行为，不以骨架数量相同、名称相似或播放器时间在走证明兼容。

角色/预设选型、参考分析与镜头候选可并行，实际轨道等统一资源/空间/事件后汇合，一个写入方提交，不导入自定义动作。
