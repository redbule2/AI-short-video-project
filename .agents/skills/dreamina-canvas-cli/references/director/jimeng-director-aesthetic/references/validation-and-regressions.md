# 验收、交付与回归

输入为原文、镜头意图、最终场景/依赖、实际画面、几何报告及保存回执。输出只覆盖已取得证据的范围；内部记录复用，不默认生成长报告、评分表或审批。

## 设计充分性：先审方案本身

在自由布局、人物路径与动作定稿前已实际读取叙事/运镜共同段，复合运动另有交接/时序条目；检查真实调用与加载→候选→联合预演→定稿的次序，不因最终列出路径就判路由生效。缺读先完成加载并重看受影响设计，不强制重做认可部分。

自主新设计的至少两个候选应给出不同的观看关系、信息顺序或空间体验。允许只在用户授权的层面调整，包括锁定场景后的镜头方案。每个beat有关注对象、可见/暂不呈现范围、动作与物件状态变化、场景和相机共同配合、转移触发及关键帧证据；无需冗长全表。情绪词、镜头名、轨迹存在和无穿模不能单独证明设计充分。

对全程完整主体平视、只整体推拉或等距跟随的候选，核对其是否只是最易执行的默认：有哪项原文要求、画内变化或持续体验支持它，另一种观看关系为什么不更合适？答案空泛则退回设计；若用户锁定或现有可见依据充分，保留该表达，不强制局部、反转或多运镜。只局部修设计及接续，然后继续制作。

方案阶段不等待动作闭环、精确坐标、碰撞或正式渲染才做P00；只交方案时标明实际画面/动作/几何不适用本阶段，不宣称制作完成。正常制作继续取得下面的实际证据。

## 设计意图在实际画面兑现

| 意图维度 | 必需的真实证据 | 未兑现时返回 |
| --- | --- | --- |
| 叙事/信息揭示 | 观众与角色何时知道什么；线索出现、反应、遮挡解除及落幅意义可看见或合理推断 | 信息顺序/虚假悬念→story-and-camera；遮挡/大小→相机与构图 |
| 观看体验 | 计划中的尺度、视差、距离、观察等待、身体参与或节奏在连续画面确实发生 | 有轨迹无所选体验→调度/构图/节拍，不自动新增剧情 |
| 人物调度 | 近远、进出画、让位/背向/交会等关系真实改变，主次注意力接力成立 | 整体站位/朝向、预设相位与事件，不修骨骼 |
| 景别/视点/透视 | 主体屏幕占比与边界、前中后景、观看位置有实际差异 | 只有“近景”名字→距离/FOV/target；不是加风格词 |
| 运镜与组合 | 位移、朝向、FOV、主体运动分别成立，交接与落幅可读 | 尖折、突然转头、尺度跳变或无意刹停→shot-recipes/timing-and-diagnostics |
| 用户行为结果 | 对象归属、起止/接触/分离或指定行动的实际状态；关键过程可见或可推断 | 动作/路径/事件；不能靠漂亮镜头抵消要求失败 |

意图可以是持续观察而非反转；静镜/全身起镜不自动低质，多切/手脚细节不自动高级。有意省略/跳切/越轴按其预期理解和重新定向线索验，不以透明连续性作为唯一风格。动作完成与P00表达分别验，避免只剩“无穿模、没有丢主角”的安全跟随。

## 实际画面与连续过程

关键画面预演先按beat对应实际帧：人物动作/相位和物件状态、场景遮挡物位置/状态、机位/target/尺度是否共同兑现所选观看关系；记录计划vs实际和未验证项。只验证相机有轨道、人物有位移或一张落幅好看都不足。已知不一致按时序参考的共同诊断处理，修改后检查问题段及前后相邻转段，有意改计划另留修订版，不覆盖初版追认。

先查起/中/末、信息出现前后、反应/注意力接力、最近障碍、转弯、接触/循环接缝和切点c−1/c/c+1。用同画幅看主体/证据占比、明暗分离、轮廓、遮挡、辨识时间，不设无来源通用像素或秒数阈值。

验收反应或接力时，先忽略镜头标题与预设名称，复用该段预演或成片，按画面回答谁先察觉、什么触发下一人、下一人的行动如何改变、观众最后看清什么。按[信息揭示顺序](story-and-camera.md#信息揭示顺序)核对最短连续段。反应有先后、第二人被切近是可记录的事实，发起与响应的关系要有单独的画面证据。用实际画面分别记下发起者、接收者和最终目标各自成为视觉重点的时点，以及让观众转看的构图、视线或切点。若只能靠动作先后推断，记接力偏弱，并回到构图、视轴或切点。需要递进揭示时，单列首个可辨线索与全貌落幅。若首次可辨时已是完整答案，按延后亮相记录，回到取景、遮挡或分镜调整。复核局部段及相邻切点即可。

用户要求解决镜头单调时，把重复段前后的实际帧或短段并排，先忽略镜号和运镜名。按[镜头太平时的设计方法](story-and-camera.md#镜头太平时的设计方法)检查观众先看谁、画面关系有何变化、哪一拍完成强调。若相邻叙事拍仍是相同主体大小、相似观察方向和均匀速度，且看不到新增的观看任务或有意的持续体验，回到机位、前景或节奏重设计该段。连续镜头检查转折前后两个观看状态。复用同一轮预演和实际画面，避免新增独立验收流程。

静帧后看连续运动：屏幕位置/尺度变化率、视轴、停留、动作相位、滑步/复位、突变/消失、部件分离及接地。硬切不掩盖未实现运动、错误路线、穿模或瞬移。表情、音效、口型和光学未实现/未验就不称成立。

正式影片解码并完整播放，文件存在、SHA、渲染回执或几张静帧不是全片质量证明。工具只能抽帧/解码时明确覆盖，不冒称完整连续观看或音效验收。网格/轴线/选择框等辅助显示不可意外当正式表达；仅用当前官方已知字段控制，未能关闭照实记限制。

## 验收抽帧上限

逐帧解码是验收里最贵的一步：实测一组 20 秒片为了“逐帧核对 480 帧”花了 218 秒，占总时长三分之一。

- **常规验收抽 6–8 帧**：每镜起/中/落 + 每个切点两侧。
- **全片逐帧解码只在交付前做一次**，不要每轮改完都重来。
- 改一镜后只复查该镜和相邻切点，不重解全片。

抽帧要能回答三个问题：这一镜是什么景别/机位、主体在画面哪里、切点两边接得上吗。回答不了再补帧，不要默认全解。

## 需求、几何与表演分层

原文逐条映射主体/人数、尺寸/距离、行为、路线、镜头、时长/画幅和修改范围。近似预设不叫精确复刻，3D原生预演不等于视频模型补全细腻表演。人物资源操作读[人物来源](execution-and-recovery.md#人物任务必读)；掌指只作可见性核对，不作数值判定。

实际制作或几何修改按[人工核对清单](collision-and-performance.md#核对流程六步)抽查，取得可复现的帧号与数值，或写清未验证项。静态装配、完整运动、同实体可动部件、物体间与激活相机分别覆盖；全部配对区间、代理、容差和未决项保留。整体人物盒不证明蒙皮/内部肢体，碰撞不等于支撑，近裁剪面另查。不能缩盒、加容差、整体豁免或合并对象隐藏问题。

合法接触限定部位/阶段，有意跳跃/飞行不强压地面；轨道没有自动豁免。复用未变承载结果，不恢复逐骨骼接地。缺代理或未决项不能叫全片通过。

## 交付层与版本对应

| 层 | 实际证据 |
| --- | --- |
| 本地工作数据 | 最终完整场景与必要依赖，定位对应影片内容版本 |
| 本地影片 | 正确相机/分镜、时长/fps/分辨率和实际全片验收 |
| 几何适用范围 | 代理/时间/容差、全部区间、覆盖缺口/未决项 |
| 远端正文 | 保存/push回执及同账号/环境show或fresh pull节点/版本/正文 |
| 远端动态 | 资源解析与实际播放，不以正文回执代替 |
| 画布影片节点 | 实际媒体节点及对应影片，不等于导演台节点 |

全部证据对应同一确定内容，不拼用旧几何、新截图和另一版影片。用户只改镜头时核对非相机对象/路径/动作/环境未变；不同审阅分支只证明自身范围，汇合后查跨角色事件、配对、切点与全片节奏。

本地影片与完整数据可独立交付；用户要求云端仍须完成，已知失败标未完成、未尝试标未验证。不要抹去本地已验证成果，也不以本地成功替代云端。

## 最终简报与回归

给最终影片/完整工作文件链接、原文符合情况、意图兑现要点、几何覆盖、技术交付层和未完成范围。必要自评以实际镜号/时间与证据表达，不默认数字评分；用户满意度不由自评代替。

修改按依赖使检查失效：相机/构图→对应画面、相机净空与激活区间；位置/路径/尺度→接触/承载/新邻居碰撞及构图；时间/fps/事件→轨道覆盖、切点和同步。只重查受影响部分，再对最终版本做必要全片核对，未变检查不反复运行。


## 观察证据、耗时与A/B

观察者保留真实设计前加载记录及布局/路径/动作定稿次序、两个联合设计候选与选择理由、分镜beat—实际帧/连续段对应、计划vs实际差异、未验证项。观察是取证，不替代执行者的需求/表演/视听/几何/技术验收，也不凭过程合规宣布B有叙事优势。

按已约定范围记录设计、制作、验证/返修、交付的起止或耗时与统计口径；缺记录标缺失，不估填。换用例仍继承耗时、A/B及交付清单，不把新用例当作取消原约定。

A/B共享同一用户任务、硬条件、技术环境与官方操作能力，分开执行与保留来源。A不加载或使用导演Skill的构思、候选、分镜、提示、诊断或B的反馈；共同官方操作资料不等于导演Skill指导。资产尽量一致，若资源、动作或场景资产不同，披露差异及可能混杂，不能仅因B流程更复杂就判优。

需要定位人物与镜头各自影响时，先对照实际角色能力、预设相位、可见触发与最终取景。还需确认单项影响时，复用同一工作文件中的短段，固定其余条件，只改角色/动作或只改调度/镜头中的一项。标为诊断复测并保留原A/B。

允许封存初版后收集反馈并做有限局部修复时，先锁定初版场景/影片与证据版本，记录反馈、修改范围及相邻转段复查。分别报告初版观察与修复版结果，修复版标为反馈后复测，不称修复后盲测。初版记录不覆盖，未完成动作不改判为兑现。后续测试使用锁定的Skill版本，测试期间不修改Skill；需要修改另开修订并重新界定测试范围。

## 叙事路由回归用例

下面是执行行为验收条件，不是本次已完成的影片测试；保留泛化输入，不携带历史实例/失败或评分。

| 条件 | 应观察到的执行行为 | 应判失败或缺口 |
| --- | --- | --- |
| 自主设计单句场景 | 先读叙事/运镜共同段，比较不同观看入口与可见变化，再定稿 | 因输入短直接选择平视全身；仅改同一轨道速度充数 |
| 局部可读但无身份悬念 | 按身体参与/动作质感/尺度体验评估局部候选，核对真实可拍范围 | 以“身份已知”排除全部局部；冒称精密手指动作支持 |
| 注意力从对象A移向对象B | 记录起始关注、实际触发、B的可读时段及落幅。若A带动B的反应，连续段要读出B因何改变以及最后看的对象 | 画面只证明两人动作有先后，或只证明切近B，便判定角色间接力成立 |
| 递进揭示承担主要体验 | 实际预演并核对可辨线索、仍保留的信息及完整答案的落幅，标出各自出现时点 | 仅推迟全貌切入，或第一处可辨画面已经交出全部答案，却判递进揭示通过 |
| 新设计复合运动 | 定稿/首次轨道前读取交接与时序条目，联合安排position/target/FOV/主体相位 | 全部导出后补读并声称已影响设计；只加smooth就称自然 |
| 用户锁定静镜/全身或只改参数 | 保留锁定表达，仅比较自由部分，核对其持续观看依据 | 强制加局部/爬升/切镜，或重做已认可设计 |
| 技术保存/解码通过但观看变化不足 | 分别给设计充分性、实际兑现、技术范围结论；不足返回相应步骤 | 用碰撞自测、轨迹存在或保存回执宣称叙事成功 |

验证读取顺序须以真实工具调用/工作记录为依据，不填推测时间。结构检查仅证明文件/引用规则，执行路由需新的隔离制作轨迹，观看效果需对应影片证据；三者不得互相替代。
