# 执行约束与失败恢复

目录：原文/版本；CLI发现；人物任务必读；并行/统一写入；低返工；渲染/发布；恢复。

## 原文、版本与修改范围

用户当前要求、原提示词及成功标准优先，Skill只补实现细节。原样保存提示词，硬条件/可调项/实现参数分开；锁定指定原工作数据与内容版本，在副本修改并保护依赖。输入简短不授权改剧情、动作、路线、人数、固定机位或情绪。

只改镜头须比较非相机对象、路径、预设片段、全局时间和环境未变；模型替换保护原动作引用。执行者沿用某初值不等于用户禁止改它，未锁定参数可在范围内协同调整。必要缺口仅阻止依赖部分，已有授权常规修正不新增审批。

## CLI发现与编辑

使用当前已安装且获授权的CLI/包，确认版本、账号、profile/区域/环境和目标项目。实际命令从当前help/schema、builtin commandFields及show读回构造，不猜接口，不以网页入口当CLI支持，不逆向私有/未获授权链路。

目录有分页按hasMore/nextOffset取得必要范围；记录稳定素材ID/用途/名称，不把临时签名URL长期保存。先读目标，再最小成功提交/预览后扩展；当前上限不等于可靠批量或耗时保证，复杂命令小批验证，不盲重放失败原子批。

新场景用 `director create` 在目标画布上创建节点；加 `--file scene.json` 可同时保留绑定到该节点的工作文件。动画选performance工作区；workspace.performance/copyStaging仅初始化/明确重建使用，避免覆盖轨道。读回内禀尺寸和锚点再按目标/源尺寸求scale，完整transform提交保留未改字段。

camera.keyframe.delete成功仍读回键ID/通道确认；未生效保留副本、按支持入口重建受影响轨道/相机并迁移分镜引用，不盲删或重做全片。关键帧按事件/曲率/可见误差选，常量通道只保留保持语义所需点，不默认全通道逐帧烘焙。

## 人物任务必读

人物本体必须标 `semanticKind: "character"`。默认用内置图元 `simple-human`，不查角色库。**用户指定库内人偶时**改用 `source:"imported"` + `rigged:true` + `resource.provider:"catalog"`，并按需挂动作片段（见[人物参考](characters-and-actions.md#库内人偶用户指定时)）。

```json
{
  "id": "hero", "name": "男主",
  "semanticKind": "character", "kind": "model", "source": "primitive", "rigged": false,
  "visible": true, "opacity": 1, "color": "#d94b4b",
  "placementAnchor": "legacy-bottom-y-v1",
  "transform": {"position": {"x":0,"y":0,"z":0}, "rotation": {"x":0,"y":0,"z":0}, "scale": {"x":1,"y":1,"z":1}},
  "primitive": "simple-human",
  "intrinsicGeometry": {"kind": "simple-human", "height": 1.75}
}
```

| 命令 | 本 Skill 用不用 |
| --- | --- |
| `director catalog --kind builtin` | 用：查内置图元与 commandFields（`simple-human` 在这里） |
| `director catalog --kind character` | **不用**：库内人偶，T-pose / K 帧 / 导入不可预览 |
| `director catalog --kind motion` | 用户要求人偶时用：50 个原地动作 + 2 个 path-traversal 走跑片段 |
| `resource` | **不用**：只有 download/get/upload |

运动走整体 transform（`position.*` / `rotation.*` 关键帧），不建 clip、不导动作 JSON。空翻 `rotation.x` 每段 ≤180°，三段 120°。

## 版本适配：先探一次再写

平台事实分三级，只有第一级能写死。

| 级别 | 例子 | 写法 |
| --- | --- | --- |
| 稳定契约 | `director-stage-cli/v1`、`object.add`、`timeline.objectTracks` | 可以写死 |
| 版本观察 | 字段是否必填、取值是否受限 | 写 + 标版本 + 给回退 |
| 已知不可靠 | 网页导出有「简化角色外形」而 CLI 没有；相机 hold 插值不可用 | 明确写“不要依赖” |

### 版本观察表

| 事实 | 首次观察 | 验证方式 | 失效时 |
| --- | --- | --- | --- |
| `cube` 用 `sideLength`，写 width/height/depth 会 invalid | 1.3.0 | 建一个 cube 跑 `director show` | 改 `cuboid`（宽高深） |
| `cuboid` 用 `width/height/depth` | 1.3.0 | 同上 | 改 `cube` + `sideLength` |
| 相机 `role` 只能是 `main` 或 `shot-camera` | 1.3.0 | 建两个相机跑 show | 全部用 `main` |
| 相机 `tracks` 必须保留 8 个通道（可为空数组） | 1.3.0 | 删通道跑 show | 补回 8 个键 |
| 相机关键帧 id 前缀 `camera-property-keyframe-` | 1.3.0 | 看 show 通过的文件 | 照抄现有文件 |
| 相机不支持 `hold` 插值 | 1.3.0 | 打两个 hold 键跑 show | 用两帧线性近似硬切 |
| 对象轨 `smooth` 在关键帧处速度降到约 40% | 1.3.0 | 匀速折线打 smooth 键，抽键前后帧比位移 | 改 `linear`；仅端点键允许 smooth |
| `--long-edge` 只收 1280 / 1920 | 1.3.0 | 传 960 看报错 | 只用 1280 |
| `director export` 无「简化角色外形」参数 | 1.3.0 | `director export --help` | 走网页导出，或场景内用圆柱 |

### 流程

1. 第一次往文件里写某个结构前，**拿最小样例跑一次 `director show`**。
2. 返回 `ok:false` 且 `reason: director.invalid_document`，按表回退，**不要原地重试**。
3. 探到新行为，补进上表并写清验证方式。

**判断标准**：条目过期不要紧，验证方式和回退路径在，就还能用。

## 场景规模与批次

实测（2026-11-12 月台 A 组）：150 个物体、42 条动作轨道时，`director apply` 出现 `40008` 超时；批次缩小后成功。

- **大批量写入前先跑探针**：用 2 个对象的最小批次 `apply` 一次，确认通道与参数被接受，再推全量。探针约 2 秒，一次 `40008` 超时约 60–170 秒。
- 单次 `apply` 控制在 24–48 条命令。
- 装饰物体能合并就合并，目标 ≤60 个；超过就分批，不要一次推。
- 物体数不是画面质量，白膜只需要能读懂空间的那个量。



## 并行执行与统一写入

简单/强耦合任务可顺序，不为并行增加角色、权限或范围。可独立查询、参考分析、资源/镜头候选并行；空间/资源、事件、fps/时长、冻结范围统一后才提交实际轨道。相机position/target/FOV/节奏由同一方案协调，互动双方共享事件/归属时间。

各分支只写独立临时目录，交只读基线版本/内容哈希、对象/通道/时段范围、提案、证据、缺口与失效依赖；不写共享场景/节点。缓存/查询按版本环境复用，不能把两个相机候选自动都写入增加分镜。

**同一逻辑场景一个写入方。**完整transform/工作区重建可能覆盖其他分支，即使不同对象也不并发写主文件或节点。汇合比基线、ID冲突、时间范围、替换粒度、互动相位/归属/视线、遮挡、切点及跨分支碰撞，重建当前完整字段；不拼完整旧场景或“最后写入胜出”。提交前读回版本、后读回核对，支持版本条件才使用，不宣称未有的原子锁。

基线过期/用户更新先保留双方、重新读取有意合并；不给旧提案自动重放。位置/路线使接触/构图/碰撞待重验，时间/fps使所有采样/同步/切点待重算，颜色只失效相关画面。没有已有并行检测器就统一顺序检查，不能只查各分支自己的对象漏跨分支配对。

## 低返工与会话独立

六步保持连续：理解硬条件→设计前加载统一视听候选→联合调度预演→制作兑现→分层审查返修→匹配交付。自由布局/人物路径/动作在共同构思与关键预演后定稿，资源能力与设计同步早查。内部检查点不是用户审批，只有方案/阶段评审请求按要求结束。精确参数逐步细化，保留初版计划、实际差异与修订理由，不用改写计划追认失败；修复复查前后相邻转段。沿用已有耗时、A/B与交付约定，换用例仍保留未交项，不重新造多份表。

问题记录对象/镜头/部位/时段、预期和实际，只修责任层及受影响依赖。先原生关键预览/问题段，不反复导整片；同因失败无新证据收束具体缺口，不扩大成工具工程。几何按[人工核对清单](collision-and-performance.md#核对流程六步)逐对抽查，不借排错恢复骨骼/掌指流程。

本次项目/素材ID、尺寸、动作、版本从当前文件/素材/CLI取得，不靠旧聊天/个人脚本/隐藏缓存；用户完整已有自定义依赖保护但不重做。暂去循环/叠加定位后恢复原任务，不用简化副本交付。

## 渲染、保存与远端发布

确认渲染器、WebGL浏览器及编码能力，和浏览器接管/网页登录权限分别诊断。预览成功、导出成功、画面达标分层；网格等session字段可能fresh pull恢复默认，正文哈希相同不证明显示同步或像素一致。

影片、场景/依赖、几何、保存回执必须同一内容。按用户交付范围执行保存/发布；保存版本/push回执不证明动作资源或动态播放。fresh pull到新文件验证引用/解析/播放，画布媒体节点另验。motion.import或director push是否发布动作库按当前官方/授权链路核验，不预设。

本地影片与完整数据可独立交付；用户要求云端时仍保留该未完成项。已有motion_not_found等失败证据写未完成，未试写未验证，不反复重制本地正确动作或用正文成功改判。不要传播凭据、私有恢复句柄或临时签名URL，不自动扩展到其他平台发布。

## 恢复先读回副作用

| 异常 | 处理 |
| --- | --- |
| 超时/取消且结果不明 | 查原文件/节点/操作状态和operationRef，再按当前恢复入口继续，不换ID盲重复创建 |
| invalid_document/引用失败 | 查类型化字段/嵌套shape、工作区、资源引用与替换粒度 |
| engine_failed | 查时间越界/资源兼容/数值，用现有最小预览定位，不臆断底层原因 |
| 版本冲突 | pull新文件、合并有意修改，再验收；强覆盖需明确授权 |
| 导出中断 | 支持时沿有效operationRef恢复，不编造命令 |
| 文件锁 | 确认持有操作，不直接删锁抢写 |
| scope/权限错误 | 核对原项目/账号/区域/环境，不篡改元数据或越权切换 |
| 渲染环境缺失 | 按实际错误处理，明确视觉验收未完成 |

只读临时失败适度重试；权限/格式/版本先修原因，不叠多层重试或猜幂等API。用户明确另存副本/新节点属于授权操作，先确认原提交状态，按独立目标串行创建一次并读回；它与超时后盲目重复不同。无新证据的相同失败保留最小复现/可用成果/具体缺口，不持续重放。
