# 即梦导演台：审美可控的镜头设计与制作

**只做一件事：把一句话的需求，变成每镜都做过明确审美选择、且能拍出来的白膜预演。**

不承担：人物表演与关节动画、材质贴图、表情口型、配音字幕、后期合成。这些做不到就写未完成，不用别的工序冒充。

## 何时用 / 何时不用

| 用户说 | 判定 |
| --- | --- |
| 「这个镜头太平」「没质感」「帮我看看怎么拍」 | 用 |
| 「做个 8 秒的雨夜巷子开场」 | 用 |
| 「照这个视频的运镜复刻一版」 | 用（重建为可编辑场景） |
| 「把这张图变成视频」 | **不用**，走图生视频 |
| 「生成一张图」「配段旁白」「加个字幕」 | **不用** |
| 「把手指摆自然点」 | **不用**，骨骼级不在范围 |

## 需求优先级

1. 用户原文、明确给定的参考与参数、已认可内容与修改范围。锁定主体、行为、时长、画幅、尺度、路径、指定镜头与交付形式。
2. 当前已验证的导演台能力决定实现与验收范围。能力不足时先调整允许变化的调度，仍不足就保留要求并注明缺口。
3. 在自由范围内，**先按叙事定观看，再按审美定参数**。影响结果的假设简要记录；关键缺失只阻止依赖部分。

## 六步工作流

1. **判断情绪与叙事，定母题。** 从原文判断这段让观众感受什么、情绪在哪个事件前后变化。用一句话写清谁在做什么、发生什么变化、观众最后该看懂什么。**每个镜头必须有且只有一个视觉母题**，写不出就说明这镜没有主张，不进入分镜表。母题不是"展示什么"，而是"这一眼看懂什么"：他在巨大的空间里很小／她的脸从暗处进入光里。
2. **按叙事与审美查景别运镜。** 在布景与角色调度定稿前，实际读取 [叙事速读](references/story-and-camera.md#镜头设计速读)、[景别与视点](references/story-and-camera.md#景别视点与透视联合选择)、[运镜入口](references/shot-recipes.md#设计前选择与加载)，并读[镜头不平的六种手法与参数表](references/aesthetics.md#手法一局部先行再给主体)、[按功能选手法的六步](references/shot-recipes.md#按功能选手法从-beat-到镜头)与[剪辑层四招](references/shot-recipes.md#剪辑层镜头之间怎么接)；出现子弹时间、速度坡道（常速-时停-加速）、升格降格时读[时间戏法](references/shot-recipes.md#时间戏法子弹时间速度坡道升降格)；人物第一次出场读[低机位出场](references/shot-recipes.md#低机位出场)。**先做情绪扫描**：列出这场戏 3–5 个情绪转折点，每个点写“观众该有的身体感”，再按[情绪 → 运镜](references/shot-recipes.md#情绪--运镜不靠触发词)选手法——不从“该放什么运镜”倒推。**每个 beat 还要定“观众是谁”**（旁观/跟随/当事人/审判/共谋），到[运镜矩阵](references/shot-recipes.md#运镜矩阵观看关系--起幅落幅)里按“起幅 → 落幅”挑手法。**景别占比、机位高度、FOV、时长一律查表定，不靠感觉；每个镜头先在“功能”列写清它给观众什么，写不出就不进分镜表**。内部比较两三条路后**只定一版完整方案**，不交付多版本：六种手法是同一场戏里的纵向组合，不是横向选项。没走的那条路压缩成一行写进镜头表的“备选”列，作为修改资源。用户已明确指定镜头时照做，不额外发散。
3. **构建角色、物件与场景关系。** 围绕关键画面确定谁关注谁、前中后景放什么、哪里遮住或露出信息。按 [输入与空间](references/input-and-space.md) 保留参考的尺度、距离、朝向、遮挡与纵深。人物资源操作前读[人物来源](references/execution-and-recovery.md#人物任务必读)。**布景覆盖每个机位方向**：每个方向都要有背景，空的用墙/柱遮挡并写进镜头表；重复件只留 3–5 个代表（见[布景](references/input-and-space.md#布景覆盖每个方向只建代表件)）。**有位移的段落，场景尺度由速度 × 时长反推**，不要先建场景再塞时间（见[尺度反推](references/input-and-space.md#尺度反推先定速度再定场景多大)）。一镜到底或 FPV 的连续穿越，以米制正投影调度图为准。
4. **调度镜头，形成渐进叙事。** 按事件节拍安排入口、变化、落幅。每拍简记观众看谁、看到什么新信息、怎么转到下一拍。需要反应、接力或揭示时按[信息揭示顺序](references/story-and-camera.md#信息揭示顺序)对齐构图、视线、切点与可见触发。**加镜头不设上限，但每加一刀必须换一项：观看位置 / 景别尺度 / 拍摄对象 / 时间点。四项全同的镜头视为重复，删掉。每一镜是一个可替换模块**：功能、起止帧、景别机位、运动各自独立成轨道，切点前后能承接，保证用户改一镜不用重做全片。 固定机位或一镜到底按用户约定执行。**插值默认 `linear`**：smooth 会让每个关键帧前后减速约 60%，匀速运动一律 linear，只有起落幅端点允许缓动（见[插值](references/timing-and-diagnostics.md#插值匀速用-linear)）。**相机轨道写完后立刻自查四项**（算式见[手算参考](references/collision-and-performance.md#手算参考)）：相机到角色的表面净空（跟拍 ≥1.2 m、贴背 ≥0.8 m、特写 ≥0.4 m）、主体占画面高（>90% 预警）、主体切边（可见 <15% 且持续 >0.5 s）、镜头时长与跨镜方向。用预览抽帧核对；不通过先改轨道，不进入渲染。
5. **预演、制作、过审美门禁。** 预演前用预览抽帧核对净空、占画面、切边与遮挡，四项都过再看画面；查 [时序](references/timing-and-diagnostics.md) 与 [验收](references/validation-and-regressions.md) 的相关段。用正式画幅先看关键构图、注意力转移、落幅与相邻切点。**常规验收只抽 6–8 帧（每镜起/中/落 + 切点两侧），全片逐帧解码只在交付前做一次**，改一镜只复查该镜与相邻切点。按[评分卡](references/aesthetics.md#评分卡0--1--2-分六项)对每镜打 0/1/2 分，六项总分 ≥9（满分 12）才交付，任一项 0 分不可交付**；7–8 分按低分项改；≤6 分重做该镜。命中[平庸清单](references/aesthetics.md#平庸清单命中-3-条即不可交付) 3 条以上，直接判不可交付，不进入修改。走跑用核验的 path-traversal，同一场景一个写入方。
6. **验收并交付。** 核对需求、实际画面的情绪与叙事变化、注意力接力、几何与技术结果。按[人工核对清单](references/collision-and-performance.md#核对流程六步)核对遮挡、穿模、悬空与相机净空，写清覆盖范围与未验证项。核对正式影片的时间轴、帧率、画幅与对应工作数据。**交付另含两样：镜头表（镜号/功能/起止帧/时长/景别机位/运动/备选）与评分表（六项分数与证据）。** 镜头表的“功能”列就是局部修改的接口：用户说保留哪镜、删哪镜、把哪镜延长，按功能定位后用备选替换并重算切点。 本 Skill 的交付物是导演台导出的预演片与工作文件；后续如何送视频模型不在本 Skill 范围，不作承诺。本地可独立交付；云端各项分别标完成、未完成、未验证。

## 交付物

按约定画幅与分辨率导出预演片，保留可编辑的场景及轨道。随片交付镜头表、带证据的逐镜评分表与记录，注明假设、还原程度及未验证项。

**兜底三条：**

- 表内无对应 → **先判是否在本 Skill 范围**（见「何时用/何时不用」）：不在范围就一句话说明并移交对应流程，不建场景；在范围才按六步工作流执行，遇到具体问题再补读。
- 多行命中 → 设计决策优先于异常处理，异常处理优先于交付核对；仍冲突就都读，只写一条结论。

## 执行护栏

**能力边界（硬）：** 人物本体必须标 **`semanticKind: "character"`**。只有两种载体：**默认 `simple-human`**；**用户指定库内人偶时用库内人偶**（`source:"imported"` + `rigged:true` + `resource.provider:"catalog"`），用户指定优先，动作在库内找最匹配的片段。需要手部时从 `simple-human` 体块内伸出长方体。两条路径下，镜头、分镜、景别、运镜规则完全一致。同一片内只用一种载体。

**动作挂载要声明**：`simple-human` 不挂 motion，运动只走整体 transform；库内人偶可挂可不挂——要表演就挂片段，用户要的是 T-pose 造型/定格/雕塑就不挂。两种都合法，但记录里要写清“挂了哪个动作”或“刻意不挂、为什么”；**既没挂动作也没写明的整体腾挪，视为遗漏**。空翻 `rotation.x` 每段 ≤180°（`0→360` 会被归一化成 0，等于没转），绕身体中心翻要给位置补偿并抽帧核对。**手部接触从体块内伸出长方体**（身体前方 0.3–0.4 m、贴住躯干侧缘，标 `prop`、名字带角色 id），不追求手指。

**审美不是可选项：** 命中平庸清单 ≥3 条、或评分卡任一项 0 分、或总分 <9 分，不得标为完成。用户明确要求平视/平光/等长镜头时按原文执行，并在记录里注明这是用户指定。破例必须写「换来什么」。

**工程：** 本版只有文档，不含脚本。写轨道之后、渲染之前，用预览抽帧人工核对：①相机到角色的表面净空、主体占画面、切边；②几何遮挡、穿模、悬空。两项都过再导出。检查结论要写清依据（帧号、量到的距离/占比），不写“看起来没问题”。
