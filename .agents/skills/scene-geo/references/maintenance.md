# 修改本 skill 的验收关

2026-08-23 事故后新增；v6 增补场景段相关项；v6.2 明确软字数目标、剧情事实优先、逐图示例与证据边界。

**教训**：v0→v3 四轮全是文本审文本——两轮对抗评审、两轮穷尽取材、九十余条意见，没有一条发现"这一格填不出来"。第一次拿真实场景跑就漏了。"三方同意文本没问题"不是合格标准。

另一个教训：方位定义绕圈的洞，两位检查者都没抓到——他们查的是"能不能构造出矛盾"，查不出"定义绕圈"。互不矛盾 ≠ 说清楚了。

以后 skill 每次改动后必须过这道门，任一项不过不算改完：

0. **冷启动填表演练（最重要；作者自己跑的不算数）**：由**没参与写 skill 的一方**，只拿 skill 文本 + 一个真实案例，逐格填模板。每格问三个问题：① 这格要用的词，skill 定义了吗？② 填不出时，skill 说了怎么办吗？③ 盖住其它行，这一行能唯一确定它说的对象吗？**任一答否 ＝ skill 有缺陷，不算演练者的错。**（作者有隐性上下文，知道每格"本来是什么意思"，所以作者产出的合格不构成证据。）
   v6 起，演练要走完整条链：底稿 → 场景段 → 轴线行，三样都填。
1. **三类黄金案例各跑一遍**：① 中央对称锚 + 四面等距墙（抓旋转多解）② L 形或多个局部锚的空间（抓单锚不足）③ 缺反打素材 + 门洞通向未知空间（抓脑补和排除项滥用）。
2. **字段级结构验收**：MAIN VIEW 是实际值不是选项 · 每个地标 AND 必填齐 · 每个开口有宿主墙段（通行口还要有连通对象）· 0 个没有证据的"已知" · 0 个阻断项进锁定版。
   v6 增：场景段里 0 个底稿记号 · 0 处把制图左右混作当镜左右 · 0 个无依据的防御性排除 · 0 句风险描述；两三句、120 字为软目标，超出本身不判废，必要信息完整优先。
3. **盲重建**：只看底稿、不看原素材，画一张俯视图；再由另一人**主动尝试画出第二张不同的合法地图**——画得出来即失败。
   v6 增：只看场景段＋场景图，也要能画回同一张俯视图（手性由场景图提供）。
4. **变异负例**（逐一注入，清单必须全部拒绝）：删掉地标方位只留距离 · 把 MAIN VIEW 改回"摄影机／地标"选项式 · 把"右端"改成"一端" · 删掉门洞去向 · 没有证据时添加"无窗无出口" · 未知墙面仍保留笼统的 SET BOUNDARY。
   v6 增：场景段里出现 M0 或 FL/FR · 场景段把未绑定具体参考图或观察基准的“画面左”当作固定布局 · 把 DRIFT-RISK 的风险描述放进场景段 · 场景段擅加无用户要求、无已批准依据的“没有第二个出口” · 把"靠门那头"改成"紧贴店门" · 场景段机械罗列不必要地标；为压到 120 字而删掉必要的出入口、朝向、连接关系或数量。
   v6.2 增：必须接受必要信息完整且无冗余的超 120 字样例，以及用户首次明确要求的唯一出口等必要事实；拒绝把剧情必需人数或道具数量延后到失败后才写、同一句合并两张场景图职责、将未经测试的模型理解能力写成确定结论。
5. **语义验收通过后**才进模型实测；模型偶然生成正确，**不能**反证多解的底稿合格。
6. **追踪表**：源条款 → skill 条文 → 模板字段 → 自检项 → 回归案例，任一列为空，不得宣布版本完成。
7. **取材搬运双向核对**：取材报告（或评审意见）里每一条编号建议，在 skill 的改动里都要找得到对应的处置（采纳／改写／驳回＋理由）。"部分采纳"和"驳回"两张清单交第三方逐条核。（v3 事故里的第 31 条就是"部分吸收、内核丢失"，死在没有这一步。）
8. **台账覆盖到定稿版**：任何一轮改动，不管来自辩论、取材还是评审，处置记录都要进 `changelog.md`；不允许"取材→定稿"这段留白。（v2→v3 是改动量最大的一轮，却是唯一没有对抗评审、没有台账的一轮。事故根因正是这张表没有：`pipeline:1002-1003` 的"相对一个声明的主视角"两家取材都挖到了，却在"证据→条文→模板→自检"的转译阶段静默掉项，台账里查不到它被讨论过。）
