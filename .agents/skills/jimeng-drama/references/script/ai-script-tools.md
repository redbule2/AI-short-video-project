# 即梦剧本生成工具

即梦自带的剧本模型 DreamScript 能生成分集大纲和单集剧本。这份文件讲它适合什么场景、入参怎么写好、结果怎么审改。命令和字段以 `jimeng-novel script --help` 为准。

## 1. 什么时候用

用户有新写大纲或剧本的需求、尚未选择方式时，先介绍“即梦 DreamScript 生成（消耗积分）”和“由你直接写（不花积分）”，让用户选择，不默认任一方式。已有明确选择时沿用，不重复问；“帮我写”“快点出”本身不代表选择。用户选即梦生成后，按铁律 1 先报价再提交；选择由你写时，按 `story-setting.md` → `outline.md` → `episode-writing.md` 执行。工具不可用或失败时说明情况，不自动切换为自写。

- 计费按产出字数，生成完才知道扣多少，`credit estimate` 也报不出价。产出长度由工具决定，事先估的总数常常偏差一倍以上，报给用户反而误导。所以提交前只说单价：「按实际产出字数扣，大约每 500 字 1 积分」，再报 `credit get` 的余额，等用户同意；不给总价或区间，也不按集数、时长去估。
- 大纲和每一集各是一次付费，每次提交前都按上面说单价、等同意。单集的入参依赖大纲，所以大纲出来、用户认可后，再提单集。
- 它没有「按意见修改」的能力。用户要改已生成的集，两种做法讲清楚让用户选：把意见写进要求重新生成（同样按字数扣，提交前再确认），或由你直接在文件上改（不花钱）。

## 2. 入参怎么写好

原则：只搬运项目文件里已有、已确认的内容，不在入参里新增设定。长文本先写进 md，用 `--<字段>-file <md>` 传，结果用 `--out <md>` 落盘（旧版 CLI 自动移进 `old/`），这样入参和结果都留在项目里可查。提交时带 `--request-id`（幂等键）：超时后带同一个 id 重跑只会找到原任务，或用 `script result --thread-id --run-id` 续查，不会重复扣费。

大纲（`script outline`）：
- 集数：README.md 里的集数。
- 创意：用户原话，加上题材、受众、基调和单集时长。工具没有时长字段，不写进创意它就不知道。
- 参考内容：已有的 setting.md 或 `source/` 里用户给的原文，原样搬运。
- 创意和参考内容至少一个非空。

单集（`script episode`）：

| 入参 | 从哪来 |
|---|---|
| 剧情定位、世界观、故事引擎、人物 | setting.md：卖点/受众/基调 → 剧情定位，世界规则 → 世界观，主线与关系引擎 → 故事引擎，人物小传 → 人物 |
| 阶段信息 | outline.md 里本集所属阶段（可选） |
| 本集梗概 | outline.md 本集整节 |
| 前情 | 前面各集梗概；集数多时压成要点，但保留没回收的伏笔和人物当前状态 |
| 上一集剧本 | 上一集定稿全文，第 1 集留空 |
| 后续梗概 | 后面最多 3 集梗概 |
| 要求 | 单集时长、台词字数和场数（按 `episode-writing.md` 第 3 节），加用户对这一集的额外要求 |

报「请求信息不合法」时服务端不说是哪个字段，对照 `--help` 查必填项、整数字段、集数范围和多余字段。其他失败（如审核）告诉用户原因，由用户决定改入参、原样再提一次（同样扣积分）还是改由你写，不自己重试。

## 3. 结果怎么审改

- 大纲：结果整理进 `story/setting.md` 和 `story/outline.md`。工具通常不产出集名、打点标签和「出场 / 场景」行，从梗概里提取补齐（整理 cast/ 要用），梗概文字不改。再按 `outline.md` 第 7 节自检，问题作为建议告诉用户。
- 单集：整理成 `episode-writing.md` 第 1 节的统一格式，只换标记，台词逐字不变；落到 `story/E0N.md`。用 `count_chars.py` 看字数是否在档，按 `script-review.md` 自检，把问题列给用户。用户选了工具，就先交原样结果，改不改由用户定。
- 交付时说明这是即梦工具生成的，报实际字数和实际扣的积分；没给过总价，就不拿它比、也不为「比预估多」道歉。
