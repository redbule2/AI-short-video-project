# 关键帧用法核验

核验日期：2026-11-10。对象：本目录 SKILL.md。上级：项目内 sd25-pe/SKILL.md。本次只修改关键帧相关骨架、规矩和自检，不改上级技能，不改现有分段提示词，不提交视频生成。

## 结论

首帧限定开始状态，中间关键帧限定指定阶段的可见状态，分镜写清状态之间如何变化。某一刻的位置、姿态不能自动扩大为整镜固定要求。保留上级要求的独立首尾帧角色句。

“定义”不是已证实的冻结触发词。带人首帧停顿、主体钉住和图外内容缺失，可能涉及图文冲突、静态约束范围、动作表达或模型自身限制；本次没有查看原始样片和完整提交参数，不能确定各自原因。更换一个词不能作为已验证的解决方案。

单张首帧模式与多图全能参考的现有对照，同时改变了模式和参考数量，不能据此判定哪种模式更容易运动。按需选择中间关键帧、按结尾对齐需求选择尾帧，是提示设计策略，不是“少挂图必定更好”的模型定律。仅借外观的图片不应额外承担关键状态职责；用户已指定的引用和职责仍须保留。

论文中的大时间步指扩散去噪时间步，不是视频开头的时间，不能据此解释“开头半秒停顿”。

## 原规则评估

| 原规则 | 评估与处理 |
|---|---|
| 首帧定义构图、位置、姿态等 | 保留职责，明确只限定视频开始时；不能要求整镜维持该姿态 |
| 关键帧定义某镜的站位与姿势 | 补上阶段和该刻状态，分镜另写到达与离开该状态的动作 |
| 有图便只写站位照图 | 缺少时间范围，也可能漏掉必要空间关系；限定时点并保留必要关系 |
| 图里有的只点名 | 适合减少重复外观，但不能据此省去主体映射、数量、归属和关键关系 |
| 各镜定稿关键帧都挂上 | 改为按职责、按需选择；不擅删用户已经指定的引用 |
| 首镜第一帧起就在动 | 按用户批注保留第一帧即动要求，并写清可见动作；这是创作要求，不是帧级结果保证 |
| 禁止固定机位，强制极慢推拉 | 删除强制拍法；相机运动不能替代主体动作 |
| 图里没有的靠文字补 | 补清出现方式与时机，并核对是否与同一时刻的图示状态冲突；不保证一定补出 |

## 与上级技能冲突：单独标出

| 条款或改法 | 冲突性质 | 处理 |
|---|---|---|
| 将固定首帧弱化为仅供构图参考 | 直接违反上级“关键帧锚点”的精确角色句要求 | 未采用；保留独立首帧角色句 |
| 为减少约束擅删已定图片引用、改其职责 | 直接违反上级“素材引用保真”和用户映射优先 | 未采用；按需选材只适用于尚未指定的素材 |
| 将每张关键帧都写成必须停留或逐帧复刻 | 直接违反上级“多关键帧顺序控制” | 写该刻状态及前后动作，不默认停留 |
| 自动挂齐全部定稿关键帧 | 条件冲突：额外激活未点名素材或覆盖已定职责时，违反上级素材映射规则 | 改为按需选择；并非图片多就一定违反上级 |
| 强制慢推慢拉 | 条件冲突：覆盖用户指定的固定机位或其他拍法时，违反上级意图优先 | 删除强制拍法，也符合本次“不定拍法风格”要求 |

“整镜站位照图”有时点歧义，本身不必然与上级矛盾；若执行成整镜保持姿态，才偏离阶段状态原则。“图里有的只点名”是过度概括，“第一帧起就在动”是过强结果表达，不能将二者一概称为上级明文禁止。

## 上级与官方接口文档的范围差异

本地上级“关键帧锚点”先说关键帧作为普通参考图输入，随后说首帧锁定输出画幅。火山2.5指南明确区分：first_frame/last_frame参数角色会锁画幅；reference_image加文字指定首尾帧不会锁画幅，结果也不完全匹配。小云雀提示词指南仍将多模态文字指定首尾帧与锁画幅连在一起，官方文档之间也存在表述差异。

该差异已单列，未用下级技能暗中覆盖上级，也未改上级文件。接口证据不能证明即梦页面实际发送了哪一种角色；本次依据用户给定的“全能参考、图片作为参考图挂载”背景评估写法，没有检查页面请求。

## 本次验证

新增或改写的关键帧规矩和自检项均不超过20字，不附例子。骨架保留占位符，不指定拍法风格。已核对首尾角色句、关键帧顺序、状态范围、动作衔接、用户引用保真与上下级一致性。

未生成测试视频，修改效果仍待样片验证。后续对照保持其他条件一致，分别测试提示词写法、关键帧数量和生成模式；每次只改一个变量，多次生成，分开观察主体与相机的运动。可固定种子时配对记录；不可固定时，单条差异不能认定为因果。
