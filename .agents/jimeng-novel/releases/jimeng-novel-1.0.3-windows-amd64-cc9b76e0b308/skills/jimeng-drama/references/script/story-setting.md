# 故事设定：从一个想法到 story/setting.md

从零写剧时用：用户只有创意、题材词或一句话。用户给了剧本、小说、梗概时看 `script-import.md`。写完设定接着看 `outline.md`。

先按题材选标准。通用要求是动机清楚、事件有因果、状态连续、内容可拍。本组文件里的反击、反派、爽点阶梯、强钩子、密集反转只适用于爽剧/强对抗题材；治愈、日常、动物戏看关系变化与情绪兑现，悬疑看问题推进与线索回收。剧情不需要时不硬加反派、秘密、金手指或危机，不适用的检查项直接标不适用。

## 1. 方向四要素

| 项 | 决定什么 | 选项示意 |
|---|---|---|
| 题材 + 核心梗 | 故事靠什么机制不断产生冲突 | 重生复仇 / 真假千金 / 契约婚姻 / 马甲掉落 |
| 受众 | 尺度、表达和观众期待 | 成人 / 青少年 / 全年龄 |
| 基调 | 流派，设定、大纲、剧本三层保持同一个（中途换流派观众会出戏）：剧情流（办成大事、层层加码）、情绪流（误会、反转、虐）、情感流（关系升温、甜虐交织） | 爽燃 / 甜宠 / 虐恋 / 轻喜 / 悬疑 |
| 集数与单集时长 | 每集装几件事、全剧分几个阶段 | 单集 30 / 60 / 90 / 120 秒；3 / 5 / 10 / 20 集 |

- 用户说过的照用；能从原话推出的（「霸总甜宠」推出女频 + 情感流）直接用，记进 README.md 的假设。缺了会让整部剧走偏的才问，一次问完，每题 2-4 个选项并标推荐；用户只想先看东西时取推荐项写下去，写完说明假设。
- 集数和单集时长决定容量，用户没给就取合理值（如 5 集 × 60 秒），写进 README.md 并在交付时点明。
- 方向很模糊（「想拍个短剧」）时给 3 张方向卡（方向名、一句话卖点、标签）让用户挑。
- 设定自相矛盾（合家欢配暗黑梗）时指出冲突并给两套最小修正。
- 用户顺口提到画风，记进 README.md，到资产阶段再定。
- 真人明星、公众人物、已有 IP 角色：按 SKILL.md 底线处理，给 2-3 个原创人设（年龄感、气质、标志特征）让用户选。

## 2. 卖点

卖点至少 3 条，每条写成一幕戏，形容词拍不出来：不写「爽感十足」，写「被泼了一身酒的真千金，当场验出那瓶酒是假货」。

从下面挑 2-3 类叠加：
1. 反差人设：身份、处境、能力错位（低位身份配高位能力、高位身份落到低位处境、职业技能跨界），要能每集产出新台词梗。
2. 信息差：观众知道、反派不知道，产生爽感；观众知道、主角不知道，产生紧张。写清谁知道、谁误会、何时露端倪、何时揭开。全剧至少一个贯穿始终的信息差。
3. 金手指 + 代价：能力要有触发条件和代价（第 6 节），否则写到第 3 集就没得爽了。
4. 名场面预埋：先想好 2-3 个能被截图转发的场面，大纲给它们留位置。
5. 期待点：前 3 集种下观众最想看的事（打谁的脸、掉谁的马、夺回什么）。

可借鉴爆款的结构手法，不照搬剧名、人物和台词。

## 3. 一句话故事

30-50 字，含主角、一个冲突瞬间和一个悬念，从具体时刻写起，不写「讲述一个……的故事」。

## 4. 人物小传

- 主要角色最多 4 个，群像最多 6 个。
- 每个主要角色五项，每项一句：身份（带一个标志性标签）/ 欲望（具体的外在目标）/ 软肋（最怕失去什么）/ 秘密（剧情不需要就标不适用）/ 人物弧光（主角写起点 → 转折 → 终点，配角写剧情功能加一次变化）。
- 张力网：至少一半角色的秘密和另一个主要角色的欲望或秘密直接挂钩，不挂钩的背景秘密不产生戏。用户已经给了人物和处境时，这几项从原话里归纳，归纳不出的标不适用，不为凑齐去补身份、经历和伏笔（边界见 SKILL.md「授权」）。
- 主角的选择要有动机，观众看得清选择和后果。爽剧首场要有主动决定和具体反击手段；治愈、动物戏可以用靠近、躲避、照料推进关系。
- 阻碍要具体；有反派就写清动机，「天生恶毒」撑不起反转。
- 命名：用户给了就照用；自己起名避开苏、沈、陆、顾、萧、叶、林等高频姓，功能性配角用老周、钱叔这类称呼。
- 外貌只写一句：性别、年龄感、一个记忆点。服装、发型、风格留给资产阶段，写在 cast/<角色>.md。

## 5. 主线引擎 + 关系引擎

- 主线引擎：主角的目标、持续制造新危机的机制、失败的代价。检验：删掉任意一集，下一集的危机还能从这个机制里长出来，否则是作者在硬推。
- 关系引擎：至少一组核心关系，写初始状态 → 至少 3 次由事件触发的变化（救命、背刺、坦白、共谋、权力倒置）→ 最终状态。每次变化都改变后面的行动或站队；误会要有真实后果，不只靠误会续命。
- 写法：`A↔B：关系定性 + 当前张力点`，如「女主↔继妹：名义姐妹，实为查账人和做账人；一笔报销款等着她查」。

## 6. 世界规则

- 每条一句，成对写触发条件和代价（或限制），共 3-6 条；单集 ≤ 30 秒的剧留 1-2 条。「女主能听见心声」要写成「女主每读一次心声，就失去自己一天的记忆」。现实题材写社会或契约规则。
- 每条规则都要在剧情里用到，最好能制造一次反转；和剧情无关的设定百科（货币、历法、地理）不写。

## 7. setting.md 写什么

标题、受众、类型与基调、核心卖点（≥ 3 条）、一句话故事、世界规则、人物小传（含别名）、主线引擎与关系引擎。

写完对照第 2-6 节的数量要求自查，再确认用户给定的名字、设定、要规避的内容全部保留，项目文件里没有真人明星、公众人物的名字。

设定可以和大纲、剧本连着写完再给用户看（多集的停点见 SKILL.md「授权」）。交付时给摘要：一句话故事、卖点、主要角色、关系引擎、适用的世界规则和做了哪些假设。用户只想聊故事时照常聊，不急着落文件。
