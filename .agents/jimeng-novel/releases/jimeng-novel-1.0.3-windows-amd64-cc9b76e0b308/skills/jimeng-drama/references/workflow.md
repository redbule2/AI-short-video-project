# 跨会话接力、回改、分批与分工

项目做到一半换了会话、要改上游设定、要决定先出哪些、或者要多集并行时看这份。

## 接着做：先看已有什么

1. 在用户启动目录找剧目录：`ls`，或找带 `.jimeng/config.json` 的目录。家目录、你自己的临时目录不是用户的项目目录。
2. 读 `README.md`：比例、风格句、单集时长、选用的模型、进度、之前做过的假设。
3. `ls story cast shots out/*`：哪些文字写好了，哪些图和片段已经落盘。
4. `jimeng-novel node list`：画布上有哪些节点、哪些在跑、哪些失败。停在「生成中」的按铁律 3 用 `node result` 查。

做完一个阶段顺手更新 README.md 的进度和假设，下次接手的人（可能是你自己）只读它就能续上。

## 改上游：找出下游再动

上游改动（角色改名、换发型、换场景、改剧情）会让下游的 md 和已生成的图、视频过期。

- 改名这类字面改动：`grep -rn "旧名" story cast shots README.md`，命中的地方全部同步改，只换这个值，顺手改别的会让已出的图和 prompt 对不上。`{{旧名}}` 和 `--ref 旧名=` 也要一起改。
- 设定改了（性别、年龄、风格）要搜的是相关特征词，不只是旧名：改性别搜代词和性别特征词（喉结、胡茬、长发这类），改风格搜旧媒介的词（写实、照片、负片，或线稿、插画）。残留一个词，模型就可能按旧设定画。
- 外观改动：改 `cast/<角色>.md` 的设定和造型小节，然后 `grep -rln "{{角色名}}" shots` 找出用到它的片段。这些片段要等新图出来再重生成才会跟着变。
- 场景、道具重出或改了描述（地标形制、陈设数量、道具外观）：分镜顶部的持续状态清单和各段正文里抄过旧描述，`grep -rn "旧描述里的特征词" shots` 找出来，改成和新图一致再提交。旧文字和新参考图冲突时，模型会在两者之间摇摆。
- 换风格：全部角色、场景、道具图和已生成的视频都要重做，花费大。先列影响范围和大致花费给用户。
- 列清楚哪些产物过期了，重做哪些由用户定（重做花积分）。不花钱的 md 你可以直接改好，改完说明改了什么。

## 多集的一致性

- 外观只写在 `cast/` 里。剧本和分镜里不写角色外貌，视频 prompt 只用 `{{角色名}}` 绑定参考。外观写在多处，改一处漏一处，各集就会对不上。
- 同一个角色全剧用同一张基础定稿图；剧情中的造型变化（换装、年龄跨度）做成造型变体（受伤、淋雨是处境，写进视频 prompt），在分段表里写清每段用哪个造型。
- 风格句、比例、模型在 README.md 定一次，全剧沿用。中途换模型，人物质感会跳。
- 跨集的状态（伤痕、道具归属、关系变化）写进 `story/outline.md` 对应集，写下一集分镜前先看一眼。

## 省钱与分批推进

花积分的环节先用小批量验证，再放量：返工的代价随批量放大。

- 拿不准 prompt 或参考图效果时，先用便宜模型、低分辨率、短时长出草稿看写法和构图，满意后用 README 里定的模型出正式版。草稿只验证 prompt，不当定稿，换模型会让质感跳。
- 视频模型里有「样片模式」时（`model list` 里名字带样片模式），可以先出 480p 样片，用户看过、点头的那几段再用 `node finalize` 转 1080p 成片。成片完整继承样片的画面、动作和时长，不像换模型出草稿那样质感会跳；没看中的段只花了样片钱。批量出片、prompt 拿不准、预算紧时主动提这个选项，用户要直接出高清就不绕。
  - 报价分两段：出样片时报样片价；转成片前对成片节点再 `credit estimate`，报价并等同意。两段分别计费，样片费不抵成片费。
  - 成片的内容全来自样片，不能单独改：要改就改样片节点的 prompt 重出样片，再转。
  - 样片只用来审片，不当成片交付，也不进最终合成（可以拼一版预览给用户看整体节奏）。
  - 告诉用户样片出来 7 天内可以转成片，过期只能重出样片；`node get` 会显示截止时间。
- 角色图先出主角，风格定下来再批量出配角；风格不对时只废几张。
- 视频先试拍一两段，见 SKILL.md「推荐流程」。
- 多集的剧，第 1 集当样板：剧本、资产、分镜、视频走完一遍，请用户确认质量和风格，再批量推进后续各集。

这些是建议，不替代报价：每一批照样按 SKILL.md 铁律 1 报价等同意。用户要一次做完就照用户的来。

## 分工：子代理

资产整理和分镜拆解很占上下文。环境支持子代理时可以派出去，每集一个分镜子代理并行，你负责复核和与用户沟通。怎么派、给什么输入见 `subagents/README.md`。

- 子代理只写 md，不花积分：报价和提交由你统一做，这样用户的一次同意只对应一份清单。
- 复核重点：台词和剧本逐字一致；`{{别名}}` 与 `cast/` 里的名字一致；时长在模型范围内；跨段的位置、朝向、道具状态能接上。
