# 剧本医生诊断

用户要「剧本医生」「剧本诊断」「剧本评估」「多维评估」「全剧诊断」「完整诊断报告」时用。对象可以是用户给的剧本，也可以是本项目 `story/` 里写好的剧本。产出一份中文 Markdown 综合诊断报告，给编剧、制片和项目评审复核。只诊断，不续写剧情，也不改剧本。不花积分。

本目录的 `prompts/` 是各评估节点的评估标准。

核心是按固定节点检查格式、开篇、主线、节奏、角色、内容审核、单集锚点和单集台词，每个结论都要有原文或节点证据，再汇总成报告。分析判断不能写成剧本里已经发生的事实；没有证据的问题不展开。

## 输入与范围

- 用户给的文件或文本：`.pdf`、`.doc`、`.docx`、`.txt`、`.md`、`.json`、`.jsonl` 都可能出现。放进项目时进 `source/`，只读。读不了的格式（比如没有工具解析 `.pdf`、`.docx`）先告诉用户，请对方转成文本或 Markdown。
- 本项目的剧本：`story/E01.md`、`E02.md`…是正文，`story/outline.md`、`setting.md` 是已有大纲。

开始前先确认，并写进报告开头：作品名（剧名字段、标题或文件名，推不出写「未提供」）、材料类型（完整剧本、局部剧本、含大纲剧本、纯正文剧本）、实际识别到的集数（按正文拆集，不按用户口头说的集数）、诊断范围（全集、前 N 集或局部）、已有大纲的状态（识别到、没识别到、识别到但没通过校验）。材料只覆盖一部分时，报告写明「局部诊断」，不当成全剧结论。

## 工作目录

中间产物和报告都落成文件，放在 `review/doctor/` 下（不在项目里时，放在输入文件旁的 `<剧名>-剧本诊断/` 目录）：

```
review/doctor/
  episodes/E01.txt …        拆集后的正文
  outline.json              结构化大纲（第 2 步）
  nodes/<节点>.json         每个评估节点的原始结果
  report_input.json         汇总给报告节点的输入（第 5 步）
  剧本诊断报告.md            最终报告
```

节点结果先落盘再汇总：中途断了可以接着做，报告里的每条结论也能回查到节点结果。

## 流程

### 1. 预处理

按「第1集」「第一集」「第 1 集」这类明确的集标题拆分正文，每集留原文、集号、标题、字数和基础问题，写进 `episodes/`。出现阻断问题时先告诉用户原因，不做完整诊断：识别不出集标题、某集只有标题没有正文、文件读不了、集号明显重复或断裂。轻微格式问题照常往下走，留给格式评估。

### 2. 大纲

标准见 `prompts/outline_extraction/outline_extraction_sp.md`，输入模板是同目录的 `_up.md`。

先看原文里有没有剧名、故事大纲、人物小传、阶段规划、分集剧情概述。字段齐全、阶段规划和分集概述的集数和正文一致时直接提取；大纲缺字段、分集概述缺集、阶段规划越界或和正文集数对不上时，按正文重新整理一份。原文大纲和正文集数不一致本身不算剧本的问题，不写进报告、不扣分，重整一份当评估输入即可。本项目的 `story/outline.md` 同样按这个标准转成 `outline.json`。

### 3. 节点评估

| 节点 | 标准（`prompts/` 下） | 检查什么 | 输入 | 输出 |
| --- | --- | --- | --- | --- |
| 格式 | `story_eval/format_judge_sp.md` | 文档结构、场次头、动作和对白标注、基础可读性 | 全部正文，不含大纲 | 0/1 分和格式问题 |
| 开篇 | `story_eval/opening_preview_sp.md` | 前 3 集有没有立住人物、冲突、卖点和追看钩子 | 前 3 集分集概述 + 前 3 集正文 | 0–3 分、亮点、流失风险、证据 |
| 主线 | `story_eval/mainline_eval_sp.md` | 主线目标、因果链、阶段推进、关键逻辑硬伤 | 全集大纲 | 0–3 分和问题 |
| 节奏 | `story_eval/pacing_eval_sp.md` | 逐集节点密度、强弱分布、空窗、爽点和钩子 | 全集大纲 | 0–3 分和问题 |
| 角色 | `story_eval/character_eval_sp.md` | 主角驱动力、配角功能、人物弧光、关系变化 | 全集大纲 | 0–3 分和问题 |
| 内容审核 | `story_eval/audit_review_sp.md` | 有明确原文证据的内容风险和人工复核项 | 全集大纲 | 0–3 分、风险项、外部核验项、送审建议 |
| 单集锚点 | `episode_eval/episode_rule_6d_batch_sp.md` | 每集和大纲、上下集、角色状态、时空状态是否一致 | 全集大纲 + 分集概述 + 一批集的正文 | 连贯、大纲遵循、幻觉扩写、角色一致、状态一致、时空一致的问题 |
| 单集台词 | `episode_eval/episode_dialogue_single_sp.md` | 台词通顺、人物口吻、场景情绪、冗余、潜台词 | 上一集 + 当前集正文，第 1 集只给当前集 | 按集的台词问题、原句、说明和修改建议 |

每个节点有一对文件：`_sp` 是评估标准，`_up` 是输入模板。执行时先读 `_sp`，把实际材料填进 `_up` 的占位符，严格按 `_sp` 规定的 JSON 结构给出结果，写进 `nodes/<节点>.json`。

- **能分给子代理就分**：环境能开子代理时，每个节点交给一个子代理，只给它这个节点的 `_sp`、填好的 `_up` 和结果文件路径。各节点互不影响判断，也能并行。环境开不了子代理时就自己按顺序做，每做完一个节点先落盘再做下一个，不让前一个节点的结论影响后一个。
- **长剧本分批**：单集锚点按几集一批做，单集台词逐集做，最后合并成全剧口径。
- 节点结果要忠实于该节点的判断，汇总时不二次发挥、不改写证据。

### 4. 分数口径

从节点结果整理各维度分数：格式 0–1；开篇、主线、节奏、角色 0–3；叙事质量 0–100，来自单集锚点；单集台词 0–100，来自单集台词评估；审核 0–3，只表示过审风险，不算进剧本质量分。没跑或没有有效分数的维度写「未纳入」。

综合质量分不用平均分、加权平均或固定公式算，要结合各维度原始分、证据强弱、问题覆盖的集数、严重度、可修复性和维度之间是否相互印证来判断。等级固定对应：S+ 95–100 优秀，S 90–94 优秀，A+ 85–89 良好，A 80–84 良好，B 70–79 合格可用，C 60–69 拒稿（中等硬伤），D 0–59 拒稿（大硬伤）。

### 5. 综合报告

标准见 `prompts/report/full_report_sp.md`。先把汇总输入写成 `report_input.json`，字段按 `full_report_sp.md`「输入内容」一节：集数、结构化大纲、各节点完整结果、各维度原始分和满分、参与质量分的维度、单独列出的风险维度（审核）、按集归并的单集锚点和台词问题索引。再把它填进 `full_report_up.md` 生成报告，写进 `剧本诊断报告.md`，结构：

1. 故事画像：题材、目标受众、一句话故事、核心卖点或观众承诺。
2. 综合结论：质量分、等级、可用性、上线建议、诊断范围、置信度、核心结论、整体优缺点。
3. 诊断问题标签：剧本设定问题、剧本质量问题，只按上游证据归因，不参与算分；没命中的标签不写。
4. 五维评分卡：格式、开篇、主线、节奏、角色。
5. 分维度诊断：格式、开篇、主线、节奏、角色、叙事质量、单集台词，每个维度结合剧情证据展开。
6. 过审风险：风险分、风险项、人工复核项、修改方向。
7. 核心问题清单：分「必须改」「建议改」「可优化」三档。
8. 分集诊断索引：每集最重要的问题、亮点和建议；没有证据的集不硬填。
9. 三轮打磨计划：结构层，场景和关系层，台词和合规层。
10. 升档路径：离下一档还差哪些确定性条件，不承诺改完一定升档。

## 表达

- 报告和回复都用中文，不出现 `must_fix`、`computed_scores`、`outline_json` 这类字段名和英文枚举；标准文件里的英文键只用于节点 JSON。
- 每个问题尽量给集数、场次和原文证据，或上游节点的证据。引原文要短，够定位就行。
- 审核风险和剧本质量分开说：质量高不等于能直接上线，过审安全也不等于好看。
- 单集台词问题有主观性，只有覆盖多集、证据清楚、影响人物或情绪可信度的，才算核心扣分依据。
- 完整报告作为文件交付：用当前环境能用的方式把 `剧本诊断报告.md` 发给用户，回复里只给简短摘要（等级、分数、最要紧的三条问题）和报告名，不在对话里贴整份报告。

## 诊断之后

报告只给建议，剧本本身不动。用户要按报告改时：用户给的原文照铁律 2 只读，改动写进 `story/`，删改台词先问；本项目自己写的剧本按 `script/episode-writing.md` 改，改完可以再诊断一次对比。

## 交付前自检

- 实际集数和诊断范围识别准了吗。
- 每个维度的输入、输出和证据来源都清楚吗。
- 审核分和质量分拆开了吗。
- 有没有机械平均、有没有没证据的判断。
- 交付的是完整报告文件，不只是摘要。
