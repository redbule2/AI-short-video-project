# 派子代理

资产分析和分镜拆解要读整集剧本、写大量 prompt，很占上下文。环境支持子代理时派出去，主代理留着和用户沟通、报价、提交。不支持时按同样的任务说明自己做。

| 工作 | 任务说明 | 并行 |
|---|---|---|
| 资产分析：剧本 → `cast/*.md` | `asset-analysis.md` | 一个子代理覆盖全部集，免得同一角色写出两份 |
| 分镜拆解：一集剧本 → `shots/E01.md` | `storyboard-breakdown.md` | 每集一个；资产已经定下来时结果最准，没定也能先派 |

## 派的时候给什么

子代理看不到你和用户的对话，也可能不在同一个工作目录，所以任务里写清：
- 项目目录和 skill 目录的绝对路径，任务说明文件全文。
- 范围（哪几集）和已确认的约束：比例、风格句、视频模型、单集时长、用户定过的外观细节（如「女主短发」）。没写进去的它就不知道。
- 只写 md 文件，可以跑 `model describe`、`count_chars.py` 这类只读查询，不建节点、不提交。这样报价和提交都由你统一做，用户的一次同意对应一份清单。

## 回来之后

子代理的自报常比产物乐观，自己抽读产物：
- cast：每个造型小节能单独提交（风格句、布局段都在正文里），外观与剧本不矛盾，没有凭空新增的角色。
- shots：台词和 `story/E01.md` 逐字一致；表里每个参考路径存在、别名和 prompt 里的 `{{别名}}` 对得上；时长在 `model describe` 的范围内。
- 小问题自己改，大问题把具体错误发回子代理重做。汇总要用户拍板的点再一起问。
